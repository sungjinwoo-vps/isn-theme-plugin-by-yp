# InfoSecNexus Private Updates

The theme and toolkit support a self-hosted WordPress update channel.

Default manifest:

```text
https://infosecnexus.com/updates/infosecnexus-releases.json
```

Default ZIP URLs generated by `tools/package.ps1`:

```text
https://infosecnexus.com/updates/infosecnexus-theme.zip
https://infosecnexus.com/updates/infosecnexus-toolkit.zip
```

## Manual Release Flow

1. Bump the theme and toolkit versions.
2. Run:

```powershell
.\tools\package.ps1
```

3. Publish these files from `dist/` to the public `/updates/` folder:

```text
infosecnexus-releases.json
infosecnexus-theme.zip
infosecnexus-toolkit.zip
```

4. In WordPress, open `Settings > InfoSecNexus Toolkit` and click `Check Private Updates Now`.
5. Open `Dashboard > Updates`, then update the theme and plugin from WordPress.

The manifest URL can be changed in `Settings > InfoSecNexus Toolkit`. A server-level override is also supported:

```php
define( 'INFOSECNEXUS_UPDATE_MANIFEST_URL', 'https://example.com/updates/infosecnexus-releases.json' );
```

## Fully Automatic GitHub Flow

The repository includes `.github/workflows/release.yml`.

When code is pushed to `stable`, GitHub Actions will:

1. Read the current theme version from `style.css`.
2. Create a build version like `0.1.9.123.1`.
3. Stamp that version into the packaged theme and plugin.
4. Patch the packaged updater endpoint to:

```text
https://github.com/sungjinwoo-vps/isn-theme-plugin-by-yp/releases/latest/download/infosecnexus-releases.json
```

5. Build the release ZIPs.
6. Publish a GitHub Release with the ZIPs and manifest attached.

Sites that installed a GitHub-generated release will then receive future update notices from WordPress automatically.

For the first public install, use the ZIP files from the first GitHub Release, not locally built ZIPs, so the bundled updater points to the GitHub release manifest.

## First GitHub Setup

Create a GitHub repository, then connect this local repo:

```powershell
git remote add origin https://github.com/sungjinwoo-vps/isn-theme-plugin-by-yp.git
git switch -c stable
git push -u origin stable
```

In GitHub, confirm `Settings > Actions > General > Workflow permissions` allows read and write permissions. The release workflow needs that permission to create releases and upload ZIP assets.

After the first workflow run completes, download and install the ZIPs from the GitHub Release. After that one-time install, future pushes to `stable` will generate update notices inside WordPress.
